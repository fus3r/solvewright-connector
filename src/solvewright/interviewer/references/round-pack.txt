# Preserve the exercise for another reader

Every Python or C++ live round must also become an executable round with no examiner. Read this before the opening. Keep a small .examiner/pack/manifest.json with the exact structure below. All asset paths are relative to .examiner/pack/, never workspace/. Copy the untouched starter here BEFORE the candidate writes code. Never copy their code or conversation into these assets.

{"format":1,"summary":"The scenario in two sentences, without the solution.","files":{"solution.py":"starter.py"},"parts":[{"number":1,"title":"Working core","minutes":5,"brief":"part1/brief.txt","rules":"part1/rules.txt","tests":{"path":"tests/test_part1.py","source":"part1/public.py"},"checks":{"path":"test_part1_checks.py","source":"part1/private.py","labels":[{"id":"test_part1_checks.py::test_boundary","part":1,"label":"Boundary case","note":"Check the boundary."}]},"solution":"part1/solution.py","files":{},"hints":[]}],"debrief":"debrief.txt"}

For C++ use solution.hpp, tests/test_part1.cpp, test_part1_checks.cpp and matching check ids. Use check.hpp as usual; the browser supplies it. For Python write pytest/unittest tests importing solution. Keep one public test file and one private check file per part. Choose unique names per part; checks must be independent of your local reference. Freeze any data/helper files in the files mappings, which map candidate-visible file names to asset paths. Put only extra data/helpers in a part's files, never a replacement solution or a test file.

Prepare ALL planned parts, their briefs/rules, runnable tests/checks, labelled notes and references before the opening, including later parts that stay private during the live round. Verify each part's reference against public/private checks accumulated through that part, and discriminate a plausible wrong solution. The brief is the full candidate-facing task and example; rules is the exact contract, or an empty text file. Preserve the original starter. When clarifying a contract or repairing a test/reference, update its frozen assets too. Never replace an earlier reference with the final reference. There may be 1 to 8 parts, each with 1 to 100 labelled checks and at most 8 optional hints. Omit hints or use [] unless you authored a ladder. Every file is at most 250000 bytes; the complete exported JSON is at most 2 MB.

At the close write debrief.txt: your reusable closing report on what the exercise tests, the design choices and tradeoffs, and what a strong answer handles per part. This is distinct from report.json's personal marks: no candidate code, quotes, names, scores, conversation or assessment. Write it even when the candidate ends early; the original planned parts remain available for solo practice. Do not claim this exercise debrief assesses the next reader.
